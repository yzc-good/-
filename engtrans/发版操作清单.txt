       英语翻译助手 · 远程更新发版操作清单
══════════════════════════════════════════════════════

本清单用于「每次要发布新版更新到平板」时照着做。
分三种场景：只发网页内容 / 只发整包 / 两者都要。

仓库：https://github.com/yzc-good/-  （蓝桥杯内容留在原地，更新文件放 update/ 目录）

──────────────────────────────────────────────
〇、准备工作（只需做一次）
──────────────────────────────────────────────
1) 所有命令都在 D 盘这个目录里打开 PowerShell 运行：
       D:\Deepseekworkplace\engtrans
2) 发布脚本、构建脚本已经就位，无需再装任何东西。

──────────────────────────────────────────────
一、改内容（在电脑上做完，才需要发布）
──────────────────────────────────────────────
1) 修改  mobile\template.mobile.html  （唯一的网页源码）
   记住：永远不直接改 mobile\www\index.html 或打包后的文件，
   一律改模板，再重建。
2) 重建网页内嵌数据：
       python build_mobile.py
   会重新生成  mobile\www\index.html（内置全部词库 + 最新界面）。

──────────────────────────────────────────────
二、决定这次发什么
──────────────────────────────────────────────
   [1] 仅网页内容热更新 —— 日常改动首选，平板免重装
   [2] 仅 App 整包升级     —— 改了原生代码/插件时才需要
   [3] 两者都要

──────────────────────────────────────────────
三、运行发布脚本（生成可上传的文件）
──────────────────────────────────────────────
       python publish_update.py
   脚本会：
   - 询问上面 [1]/[2]/[3] 选哪个；
   - 把 mobile\www 打包成  web-数字.zip（数字每次 +1）；
   - 需要整包时，让你选一个已签名 APK 并拷贝进来；
   - 生成  update.json（含文件大小 + SHA-256 校验值）；
   - 输出结果到  D:\Deepseekworkplace\engtrans\publish_update\
   结果目录会包含：
       update.json     ← 更新清单（App 靠它判断有没有新版）
       web-数字.zip     ← 网页内容包（热更新用）
       ….apk            ← 新版整包（选整包时才有）
       .version         ← 内部记录，下次自动递增（留着别删）

──────────────────────────────────────────────
四、上传到 GitHub
──────────────────────────────────────────────
1) 打开仓库网页：
       https://github.com/yzc-good/-/tree/main/update
   （若没有 update/ 目录就先新建它）
2) 把  publish_update\ 里刚生成的文件（update.json、
   web-数字.zip、以及 APK，如果选了）全部上传/覆盖到 update/ 目录。
   ⚠️ 覆盖 update.json 和新增的 web-数字.zip，旧 zip 可留可删。
3) 提交并推送到 main 分支。等 GitHub 刷新（一般几秒）。
4) 检查发布是否生效（用电脑浏览器或平板访问）：
       https://raw.githubusercontent.com/yzc-good/-/main/update/update.json
   能看到新的 webVersion / web-数字.zip 即可。

──────────────────────────────────────────────
五、平板上更新（提供给使用者）
──────────────────────────────────────────────
1) 确保平板已连网。
2) 打开 App，点标题栏「🔄 更新」。
3) 看到提示后选：
   - 「仅更新应用内容（热更新）」→ 几秒完成，自动重载；
   - 若同时有整包，还会弹「下载新版 App（整包安装）」。
4) 更新内容来源（App 内置，可改）：
       https://raw.githubusercontent.com/yzc-good/-/main/update/update.json
   若想换仓库/镜像，改  mobile\android\app\src\main\java\com\engtrans\app\UpdateManager.java
   里的 DEFAULT_MANIFEST_URL 后重新构建 APK。

══════════════════════════════════════════════════════
附录 A · 需要发「整包升级」时的完整链路（较少用）
══════════════════════════════════════════════════════
改原生代码后，除了第二步的 build_mobile.py，还要：
1) 同步网页到 Android 工程：
       cd mobile
       node node_modules\@capacitor\cli\bin\capacitor sync android
2) 构建 APK（在 mobile\android 目录）：
       gradlew.bat assembleRelease
   需先设置环境变量（PowerShell 内运行时）：
       $env:JAVA_HOME='D:\Deepseekworkplace\engtrans\tools\jdk21\jdk-21.0.12.1+1'
       $env:ANDROID_USER_HOME='D:\...\tools\android-user-home'
       $env:GRADLE_USER_HOME='D:\...\tools\gradlehome'
   产物在  mobile\android\app\build\outputs\apk\release\app-release-unsigned.apk
3) 签名（回 engtrans 根目录）：
       tools\sdk\build-tools\35.0.0\apksigner.bat sign ^
         --ks tools\engtrans.keystore --ks-key-alias engtrans ^
         --ks-pass pass:engtrans2024 --key-pass pass:engtrans2024 ^
         --out EnglishTranslator-vX.Y.apk ^
         mobile\android\app\build\outputs\apk\release\app-release-unsigned.apk
4) 版本号要先改：mobile\android\app\build.gradle
       versionCode（整数，须比上一个大）
       versionName（如 "1.3"）
5) 然后回到第三节，运行 publish_update.py 选「整包」即可。

附录 C · 版本号一致性（重要，别踩坑）
══════════════════════════════════════════════════════
   1) mobile\android\app\build.gradle 的 versionCode / versionName
      → 决定「整包升级」是否提示（远端 versionCode 更大才提示）。
   2) mobile\www\VERSION（内容是数字，如 3）
      → 决定「网页内容」的基线版本，必须等于本次发布包里的
        webVersion，否则装完新包会提示一次多余的热更新，
        甚至把新界面替换成旧内容。
   3) publish_update\.version
      → 脚本自动记录上次发布的 webVersion，下次自动 +1。
      若手动删了它，脚本会从 1 重新开始，务必改回正确的数字。
